One row per manifest name. Cell links point to the evidence line in the plugin repository at its pinned commit.

Fields: `name/repo/sha/tier` identify the pinned input; `entry/kind/hooks` identify the selected integration; `tools` lists exact static names and citations; `tools_note` records conditional exposure; `forget_tool` and `engine_delete` are separate. `engine/store/account` describe dependencies, storage and account requirements. `sec` covers paths, environment, direct access, database credentials, egress and telemetry. `context` records host insertion rules, actual hook source operations/returns, source stores, bounds and built-in-memory handling. `tests` contains counts, coverage limits, deletion-related examples and a cited per-file inventory. `license/commit_date/repro/runnable` cover the remaining checks. `audit_scope` lists files inspected and snapshot limits; `note`, `spot_check` and `b3_fetch` record qualifications and follow-up evidence.

Values: `forget_tool=yes` means an exposed operation can delete, retract, archive or otherwise explicitly retire stored content; it does not mean physical erasure. `update_only` includes correction/supersession while retaining history. `none` means the inspected native surface has neither; `unknown` means the surface cannot be established. `engine_delete=yes` requires a source-visible API/CLI/SDK deletion or retirement path, including a forwarding SDK call; it does not prove the remote implementation or all-copy erasure. Its scope can be narrower than facts, such as session/index/audit deletion. `not_in_repo` means the relevant engine implementation is absent; `none` means no such operation was identified in the inspected implementation. A terminal can still edit local files regardless of this flag.

Kinds: `provider` means a MemoryProvider subclass or a shim resolving to one; `provider_context` also supplies a context engine; `provider_hooks` adds general hooks; `context_engine` is not a MemoryProvider; `tools_hooks`, `tools_only`, `hooks`, `skill_only`, `skill_mcp`, `mcp`, `mcp_remote`, `external_shim`, `auxiliary`, and `unavailable` describe the remaining entry paths. Hook inventories include configuration and tool callbacks as well as lifecycle callbacks. Conditional schemas are a union of code-visible registrations, not a claim that every tool appears in the default configuration.

Method and limits: static source inspection only. No network requests, installs, plugin imports/execution, tests, commits or deployments were performed. Historical notes were used as leads, not as current test results. `yes` under runnable means a code-supported accountless mode after installing its ordinary dependencies, with an existing Hermes host assumed; it is not an executed clean-box test. `needs key` includes an account/login or the default model key, `needs server` includes a local embedding/model service, and alternative modes are explained in JSON. No row was classified as requiring a GPU without explicit evidence. `unknown` remains a valid result.

Test counts are recognized static declarations, not collected cases, passes or coverage percentages. The scanner counted Python `def test_*`, JS/TS `it(`/`test(`/`Deno.test(`, Go `func Test*`, Rust test attributes and shell `@test`; dynamic/parametrized cases are not expanded. Inline Rust tests were included. `tests.inventory` carries a citation and count per retained test file. A deletion-related test name can concern cache/session cleanup, so its body must be read before treating it as an erasure test. A zero means no recognized declaration in the snapshot, not proof of no upstream tests.

Commit dates are unknown for all 130 rows. The manifest carries SHAs but no commit timestamps, and the snapshot excludes `.git`. Missing lockfiles also cannot be called absent upstream: `fetch.py:12` (our fetcher) explicitly filters `.lock` files, while `fetch.py:41` (our fetcher) filters source entries. Retained JSON/YAML locks and `go.sum` are listed where present. Package ranges and mutable download/model tags are preserved in `repro`; a pinned repository SHA alone does not freeze those artifacts.

Host boundary: an external provider adds its static prompt block and dynamic prefetch path; built-in memory has separate enable flags.
